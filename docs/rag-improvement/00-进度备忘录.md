## 0. 总目标

把 RAG 从「向量检索 + 一次性总结」改造成**可被主 Agent 调用、可评估、可观测、可追溯的知识检索子 Agent**：

- 输出结构化 `evidence[] + answerable`，而不是不可追溯的一段话；
- 每个块有稳定 `doc_id/version/chunk_id/parent_id`；
- 文档更新/删除可传播（修复 TD-07）；
- Dense + BM25 + RRF + Rerank 的混合检索；
- Golden Set + 检索指标回归；
- 父子扩展、可回答性判断、trace、缓存、注入防御。

## 3. 本次关键决策（持续追加）

1. **语料**：`论语.pdf`（52 页，约 40 页正文）作为主评测语料；需求文档转成 `rag_requirements.txt` 作为第二语料。后者与 `.docx` 一样不纳入版本管理，避免内部文档进 Git。
2. **评测集拆分**：`eval/golden_set.jsonl`（论语，可提交、可复现）与 `eval/golden_set.local.jsonl`（需求文档，本地生成、gitignore）。
3. **新集合名**：`agent_v2`，避免与旧集合 `agent`（3 条脏数据、无元数据）混用；旧集合保留不删。
4. **BM25 自研**：不新增 `rank_bm25` 依赖，用**中文字符 unigram + bigram** 的 BM25，兼顾古典汉语与英文标识符。
5. **Rerank**：验证期先用 DashScope `gte-rerank-v2`（已实测可用）；后续模型对比后默认切 `qwen3-rerank`（见第 9 条），失败/超时则降级为 RRF 排序并标记 `degraded_stages`。
6. **状态机**：严格按 v2 契约 `ok | no_evidence | degraded | denied | error`；`error.code` 使用 `INVALID_QUERY / INDEX_STALE / TIMEOUT / UPSTREAM_5XX / RATE_LIMIT`。
7. **日志不落全文**：只记录 `query_hash`、`doc_id` 列表、状态、分段延迟；不记录完整 query 与证据正文（v2 §3.2）。
8. **git 历史**：只新增分支/提交与 `git rm --cached`（运行产物从索引移除），不重写、不删除任何历史提交。
9. **rerank 选型**：`qwen3-rerank` 作为默认推荐（R@10 0.8061 / MRR 0.7722 / 433ms）；`qwen3-vl-rerank` 排序略好但更慢且分数不可用于 Answerability 阈值；`gte-rerank-v2` 本轮落后。详见 `07-rerank模型对比报告.md`。
10. **道德经用途**：作为第二评测语料（`agent_dd`，1543 子块 / 32 条 Golden Set），不做训练集；两版并存用于版本/注家混淆测试。

## 4. 已知限制 / 后续待办

- 需求文档转换文件不入库，评测时需要本地生成（脚本 `eval/prepare_local_corpus.py`）。
- 无 OCR，扫描版 PDF 仍无法解析（沿用 TD 记录）。
- 无真实 ACL/多租户，`scope` 仅支持按元数据精确过滤的接口形态。
- 答案生成仍是单次 LLM 调用；多轮指代消解由主 Agent 负责（v2 §9 非目标）。
- 模型/Embedding 升级迁移（双写/别名切换）未实现，只有 `index_version` 校验兜底。
