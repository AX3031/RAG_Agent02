## 1. 新增的工具：`retrieve_knowledge`

原来的 `rag_summarize(query) -> str` 保留（向后兼容），新增：

```python
@tool(description="从企业知识库检索证据，返回结构化 JSON ...")
def retrieve_knowledge(query: str) -> str:
    return rag.retrieve(query).to_json()
```

主 Agent 现在有 9 个工具：

```text
retrieve_knowledge / rag_summarize / get_weather / get_user_location /
get_user_id / get_current_month / fetch_external_data /
fill_context_for_report / web_search_baidu
```

主提示词（`prompts/main_prompt.txt`）新增约束：

- 需要可追溯出处时优先 `retrieve_knowledge`；
- `answerable=false` / `no_evidence` 时**不得用自有知识补全**；
- `degraded` 时可用证据，但要意识到精排已降级；
- 引用时给文件名/标题/页码，不暴露内部 `evidence_id`。

即使工具返回 `answerable=false`，主模型仍会用历史知识解释（实测）。`ReactAgent` 增加：

```python
REFUSAL_TEXT = "根据现有资料无法回答该问题。"

def _knowledge_insufficient(messages):
    # 反向查找最后一次 retrieve_knowledge
    # 若 status=no_evidence/error 或 answerable=false → True
    # 若中间有 web_search_baidu/fetch_external_data → False
```

命中时，最终输出被**强制替换**为拒答文本。实测：

```text
输入：《论语》中孔子如何看待量子计算机？
输出：根据现有资料无法回答该问题。
```

## 6. 整体反思

### 做得最好的三件事

1. **先建评估，再改系统**：没有 `eval/` 就没有后面所有“收益”数字；
2. **契约先行**：`evidence[] + answerable + status` 让 RAG 从“一段话”变成“可编排的子系统”；
3. **确定性护栏**：证据不足时强制拒答，把“不要幻觉”从提示词口号变成代码约束。

### 最需要继续做的五件事

1. **查询改写**：`ly-005` 这类“现代词 vs 古典词”失败，靠混合检索救不回来；
2. **Golden Set 扩容 + holdout + 双人标注 κ**：当前规模与一致性不足以支撑上线承诺；
3. **生产化索引**：软删除/tombstone/GC、ingestion 队列/DLQ、embedding 迁移双写；
4. **CI 门禁**：把 `baseline.json` 对比脚本化，每次改 RAG 自动跑；
5. **真实 ACL 与可观测平台**：`scope` 接鉴权上下文，trace 接 Langfuse/Phoenix。

### 一句话总结

> 这次改造把 RAG 从“向量检索 + 一次性总结”推进到了“有契约、有评估、有降级、有护栏的检索子 Agent”；它不是生产终态，但已经具备**用数据驱动下一步**的能力。
